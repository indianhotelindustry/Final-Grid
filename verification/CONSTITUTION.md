# The Financial Constitution — FinalGrid

Phase 2.6. Engineering law for this project.

This file is the human-readable form of a machine-readable registry. The
operative text lives in `verification/invariants/model.py` as
`PRINCIPLES` and `STRUCTURAL_ENFORCEMENT`; the coverage report at
`python -m verification inv-registry` is generated from it. **The registry
is authoritative and this document is transcribed from it**, not the other
way round — so a principle cannot be amended here without amending the
code that enforces it, which is the property that stops a constitution
becoming decoration.

Every invariant names the principles it enforces. The engine reports
coverage per principle, so a principle with no invariant is *visible as a
gap* rather than assumed to be satisfied.

Wave 0.5, 2026-08-07. The Phase 2.6 source document was not present in the

## 1. The principles

Fourteen principles are registered. Each is marked with how it is
enforced:

- **invariant** — an obligation of the *system*. Enforced by one or more
  registered invariants that can be evaluated against the database and
  can fail.
- **structural** — an obligation of the *verification framework itself*.
  Enforced by the shape of the framework: by the commissioning gate, by
  the evidence model, by the registry's refusal to accept an
  under-specified declaration. These cannot be expressed as a query over
  the data, and listing them as "uncovered" would be as misleading as
  quietly counting them as covered.

| # | Principle | Enforcement |
|---|---|---|
| **P1** | One canonical derivation | invariant |
| **P2** | Frozen historical values remain immutable | invariant |
| **P3** | Reports consume canonical engines | invariant |
| **P4** | Night Audit orchestrates rather than derives | invariant |
| **P5** | Validation occurs at the service layer | invariant |
| **P6** | Evidence must be capable of falsifying a change | structural |
| **P7** | Closed periods are append-only | invariant |
| **P8** | One temporal basis | invariant |
| **P9** | Controls must be capable of failure | structural |
| **P10** | Absence of evidence is not evidence of correctness | structural |
| **P11** | Observable correctness | invariant |
| **P12** | Historical immutability | invariant |
| **P13** | Verification before implementation | structural |
| **P14** | Every financial object has provenance | invariant |

### How the structural principles are enforced

Stated so the claim can be checked rather than taken on trust. Transcribed
from `STRUCTURAL_ENFORCEMENT` (`invariants/model.py:75-93`).

**P6 — Evidence must be capable of falsifying a change.**
Every invariant must declare a `negative_seed` or a `negative_patch`: a
concrete way it could be made to fail. Registration refuses one that
declares neither, so an invariant incapable of falsifying a change cannot
enter the registry.

**P9 — Controls must be capable of failure.**
Commissioning demonstrates the failure of every invariant across eight
elements. Until it has, the invariant's result is reported but excluded
from every verdict.

**P10 — Absence of evidence is not evidence of correctness.**
An invariant evaluated over an empty population reports `VACUOUS`, never
`HOLDS`, and `VACUOUS` keeps the run at `INCOMPLETE` rather than `PASS`.
The same rule governs D1: two implementations that both return zero over
an empty set have not been shown to agree about anything.

**P13 — Verification before implementation.**
Wave 0 builds the verification framework before any financial logic is
changed, and D5 challenges every layer of it with realistic faults before
that framework is relied upon. Structurally, the registry refuses an
invariant that cannot state how it would fail, so no obligation enters the
system without its verification.

## 3. Open constitutional questions

Recorded rather than resolved, because constitutional text may not be
invented to make a document look finished.

### 3.1 P15 — declared but not registered

The project charter describes the constitution as **P1–P15** and lists
*"Independent evidence"* among its principles. There is no `P15` entry in
the registry and no `P15` reference anywhere in the codebase.

Mapping the charter's list against the registry: twelve of its bullets
correspond exactly to registered principles; *"Independent evidence"*
corresponds to nothing. It is the plausible P15, but its authoritative
wording, its enforcement class, and whether it is invariant-enforced or
structural are not recoverable from the repository.

**Status: `DECLARED — NOT REGISTERED`.** Until the Phase 2.6 source is
recovered or the wording is restated by the project owner, P15 is not
enforced, is not counted in coverage, and must not be cited as governing.
An unregistered principle is exactly the kind of unfalsifiable claim P6
exists to forbid.

Note that if P15 *is* "independent evidence", the framework is already in
tension with it: Phase 2.6 §10 requires certification evidence to live
outside the application, and all 81 evidence packs are currently stored
inside it (`verification/evidence/`).

### 3.2 Two stale range claims, now corrected

Three sources stated the constitution's extent and two were wrong:

| Source | Claimed | Correct |
|---|---|---|
| `invariants/model.py:21` docstring | P1–P12 | P1–P14 |
| `invariants/report.py` coverage heading | "P1 to P12" | P1–P14 |
| `invariants/model.py:55` `PRINCIPLES` dict | P1–P14 | authoritative |

P13 and P14 were registered, enforced and reported throughout while two
labels continued to say the constitution ended at P12. Corrected in Wave
0.5; comment and heading text only, no behavioural change.

### 3.3 The `P` namespace collision, resolved in Wave 0.5

Constitutional principles (`P1`–`P14`) and D1 parity quantities
(`P01`–`P22`) shared a prefix. `README.md` line 357 read *"P11 and P21 are
VACUOUS"* — quantities — while `datasets/model.py:55` read *"P11
(observable correctness)"* — a principle. Two different P11s in one
framework, one of them constitutional.

Wave 0.5 renames the quantities to **`Q01`–`Q22`**. Principles keep `P`.
Stored baselines and retained evidence packs are **not** rewritten — that
would violate P12 — so a legacy alias resolves the old identifiers on
read. See `ENGINEERING_GUIDE.md` §6.

## 4. Amending this constitution

1. Amend `PRINCIPLES` in `verification/invariants/model.py`. A principle
   that is not in that dict is not enforced, whatever any document says.
2. If the principle is **structural**, add its entry to
   `STRUCTURAL_ENFORCEMENT` stating the mechanism concretely enough to be
   checked. Registration of a structural principle with no stated
   mechanism is refused.
3. If the principle is **invariant-enforced**, register at least one
   invariant naming it. A principle with no invariant reports as a
   coverage gap on every run and blocks certification.
4. Re-run `python -m verification inv-registry` and confirm the new
   principle appears with its enforcement.
5. Transcribe the change here, including the coverage table.
6. Commit the code change and this document together. A constitution
   amended in prose alone has not been amended.
